# DashboardX · Недвижимость / Realty Radar

Фронтенд: \`client/_realtyRadar.html\`, \`client/js/module/Widget/RealtyRadar.js\`,
\`client/js/module/Widget/RealtyRadarAnalysis.js\`, \`client/css/module/widget/realty-radar.css\`.

## Что уже работает

- Четыре вкладки: долгосрочная аренда (месяц), аренда с последующим выкупом, короткая аренда (час/сутки), продажа (включая земельные участки, дома, коммерцию).
- Для аренды заданы Нуркена Абдирова, Лободы, Ерубаева, Гоголя; отключить галочки — весь город. Для продажи изначально доступна вся Караганда.
- Бюджеты по умолчанию: 150 000 ₸/мес, 150 000 ₸/мес, 25 000 ₸/сутки или час, 40 000 000 ₸ за объект. Меняются отдельно по каждой вкладке.
- Параметры сохраняются по ID экземпляра виджета в штатном DashboardX \`ClientDB\`. Данные разных экземпляров не смешиваются.
- Импорт/экспорт JSON; поиск; фильтры; избранное; сохранение первой даты появления; изменение цены; отметка пропавших из ленты.
- При наличии **разрешённой** HTTPS JSON-ленты — обновление при каждом открытии виджета и кнопкой вручную. Текущая дата источника должна передаваться как \`generatedAt\`. Ошибки CORS, HTTP, тайм-аут и старые данные показываются явно.
- Алгоритм даёт скидку к медиане **только при наличии минимум трёх** сопоставимых объявлений того же типа, вида недвижимости и периода оплаты, а для квартир — одинаковой комнатности и близкой площади. Это сигнал к изучению, не подтверждение реальной рыночной цены.
- Для выкупа фильтр бюджета использует **платёж по договору**, если он известен, иначе объявленную аренду.
- Вкладка с выкупом **не гарантирует** наличие такого юридического предложения; если договорный платёж или общая цена неизвестны, выводится предупреждение.
- Быстрые переходы на поиск Krisha, OLX и KN. Эти ссылки не обходят защиту и не загружают данные в виджет.

## Формат разрешённой ленты

\`\`\`json
{
  "generatedAt": "2026-11-01T10:00:00+05:00",
  "items": [
    {
      "title": "2-комнатная квартира",
      "url": "https://example.org/listing/100",
      "source": "Authorized feed",
      "category": "monthly",
      "price": 120000,
      "priceUnit": "month",
      "address": "Гоголя, 41, Караганда",
      "rooms": 2,
      "kind": "apartment",
      "area": 48,
      "sellerType": "owner",
      "postedAt": "2026-10-31T12:00:00+05:00"
    },
    {
      "title": "Квартира с возможностью выкупа",
      "url": "https://example.org/listing/101",
      "category": "rent_to_own",
      "price": 115000,
      "priceUnit": "month",
      "address": "Лободы, 12, Караганда",
      "rooms": 2,
      "area": 44,
      "purchasePrice": 12000000,
      "downPayment": 2000000,
      "contractPayment": 140000
    },
    {
      "title": "Земельный участок",
      "url": "https://example.org/listing/102",
      "category": "sale",
      "kind": "land",
      "area": 700,
      "priceUnit": "total",
      "price": 11000000,
      "address": "Караганда"
    },
    {
      "title": "Посуточная квартира",
      "url": "https://example.org/listing/103",
      "category": "short",
      "price": 13000,
      "priceUnit": "day",
      "rooms": 1,
      "address": "Ерубаева, Караганда"
    }
  ]
}
\`\`\`

\`area\` задаётся в квадратных метрах, в том числе для участка. Категории:
\`monthly\`, \`rent_to_own\` (или \`buyout\`), \`short\`, \`sale\`. Период цены:
\`month\`, \`day\`, \`hour\`, \`total\`. Опциональные поля:
\`description\`, \`sellerType\`, \`postedAt\`, \`purchasePrice\`, \`downPayment\`, \`contractPayment\`.

Для сети требуется HTTPS + CORS, разрешающий домен DashboardX. Не размещать ключи API в URL или публичном JSON. Контролировать размер и чистоту входных данных на сервере. В браузере входные строки выводятся через \`textContent\`.

## Важно: подключение реального ежедневного сбора

Это первая интегрированная версия **без самостоятельного незаконного парсинга** и без публичного сервера-агрегатора. Для полноценного ежедневного потока предложений нужно заключить договор / получить разрешение источника или получить легитимную лицензированную/собственную ленту. Krisha.kz запрещает автоматическое извлечение объявлений без письменного разрешения (пункты 5.3–5.4 пользовательского соглашения, https://krisha.kz/content/special/agreement).

Не нужно менять существующий Railway PRO OPTIMA: разместить отдельный источник или бекенд, выдающий согласованную JSON-схему. Не подключать к production PRO OPTIMA таблицам, поставщикам или заявкам. Сохраняемые настройки текущей версии — локальные в браузере и не синхронизируются между устройствами.

Сроки обновления **определяются поставщиком данных**; просто обновление страницы не гарантирует новых объявлений. Для непрерывного мониторинга на Railway нужен отдельный планировщик/воркер разрешённой ленты и база истории.
