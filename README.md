`backup/main-before-ar-horizon-redesign-20261025`.

## Рабочие пространства из Settings и Spatial 3D

Виджет **«Настройки DashboardX»** теперь содержит раскрывающиеся блоки:
рабочие пространства, управление интерфейсом (все кнопки верхней шапки),
подключения, OpenAI AI и сброс данных. Создавайте отдельные рабочие столы
**«Дом», «Улица», «Кафе»**, меняйте названия и переключайтесь между ними.

В **Spatial 3D** постоянно доступен селектор пространств: создавать и
переключать пространства можно даже тогда, когда на выбранном рабочем столе
нет виджета «Настройки». При переключении приложение остаётся в 3D.
Положение одного и того же виджета в 3D сохраняется отдельно для каждого
рабочего пространства.

Настройки сохраняются в браузере, **не синхронизируются автоматически между
устройствами**; использование геолокации и автоматическая смена пространства
пока не реализованы. [Инструкция](docs/settings-workspaces.md).

## Виджеты

**Все 16 исходных типов**, включая системный `add`, явно зарегистрированы в объекте `WIDGET_CATALOG` внутри `client/js/index.js`. Категории оригинальных шаблонов: `system`, `finance`, `tools`, `media`, `games`, `telegram`. Названия категорий отображаются ЗАГЛАВНЫМИ.

Список в постоянном системном виджете «Добавить виджет» берётся из реестра, **а не из результатов загрузки HTML**. Неудачная загрузка отдельного шаблона не удаляет тип из списка: при добавлении отображается сообщение о недоступном шаблоне.

В автономном режиме теперь работают локальная диагностика `serverConsole`, Telegram-редактор черновиков `telegramBot`, аудиоплеер `audioPlayer`, видеоплеер, NES, списки желаний и прочие локальные виджеты. Полноценная автоматизация Telegram-бота, непрерывный приём сообщений, AI-шлюз и загрузка торрентов по-прежнему требуют внешней инфраструктуры или клиента.

Каждый пользовательский экземпляр имеет уникальный ID. Существующие экземпляры можно показать на другом рабочем столе; копирование создаёт новый независимый ID. Начальная страница не создаёт демонстрационных экземпляров или транзакций.

## Горячие клавиши

- **D + Alt + Tab**: удерживайте D и Alt и нажимайте Tab, чтобы переключаться по созданным рабочим столам по кругу, не перезагружая страницу.
- **D + Alt + Shift + Tab**: в обратном направлении.
- **D + Alt + → / ←**: альтернативный способ, когда Alt + Tab перехватывается операционной системой и не доходит до браузера.

Сочетания работают, только пока страница получает события клавиатуры. В Windows и некоторых окружениях **Alt + Tab** всегда переключает системные окна, и сайт не может отменить это поведение.

## Данные и ограничения

`localStorage` сохраняет изменения, но не синхронизирует устройства и не шифрует содержимое. Очистка данных DashboardX требует подтверждения. Старые секреты и персональные данные могут оставаться в других ветках и истории Git и должны быть отозваны/очищены отдельно.

## Внутреннее состояние виджета «Курсы валют»

Виджет `moneyConvertApi` больше не отображает заранее заданные строки KZT, RUB, ETH.
При первой настройке список пар **пустой** — старые курсы и настройки из прежнего виджета не импортируются. Существующие рабочие столы, другие виджеты и финансовые операции не удаляются.

1. В первом поле выберите **исходную валюту** через поиск по началу кода или названия, например `US` → `USD`.
2. Во втором выберите валюту **назначения**, например `KZ` → `KZT`.
3. Нажмите «Добавить пару». Ниже появится курс `1 USD = ... KZT`, рассчитанный по MoneyConvert.
4. Добавляйте дополнительные пары и удаляйте ненужные крестиком. Повторное добавление одной и той же направленной пары запрещено.

Список доступных валют подгружается из <https://www.moneyconvert.net/api/>; API возвращает котировки всех валют относительно USD. Значение `FROM → TO` равно `rates[TO] / rates[FROM]`, обновление — примерно раз в пять минут.

**Где хранится память:** `localStorage["dashboardx.local.v1"].instances[instanceId].widgetState.pairs`, например `[{"from":"USD","to":"KZT"}]`. Числовые котировки **не сохраняются**: они загружаются заново. У разных ID собственные списки пар. Если один и тот же ID показан на двух столах — настройки общие, при создании новой копии они пустые. Старый глобальный кеш `rate` очищается без удаления остальных данных.

Если MoneyConvert недоступен, виджет явно сообщает об ошибке. Уже сохранённые пары остаются на месте, но вместо неподтверждённого курса отображается сообщение об отсутствии значения.


## Правило проекта — API-токены и секреты

**Актуальное правило:** Telegram API Token и PRO-OPTIMA Admin Token вводятся в одном системном виджете `dashboardSettings`. По явному выбору пользователя оба сохраняются в `localStorage` (`dashboardx.credentials.v1`) **без шифрования**. Не публиковать токены в GitHub, исходниках, параметрах URL или логах.

`dashboardSettings` сохраняет токены между перезапусками на том же происхождении (origin). Браузерное хранение не защищает от XSS и других скриптов на том же домене GitHub Pages, в том числе из других репозиториев владельца. Используйте этот режим лишь на доверенном устройстве. Telegram Token пока хранится для будущей интеграции, а PRO-OPTIMA Admin Token отправляется **только** как Bearer-заголовок к Railway API при работе с PRO-OPTIMA.

## ID виджетов и переходы

Каждый тип нумеруется независимо с `000`: `moneyConvertApi-000`, `moneyConvertApi-001`, `moneyConvertApi-002`. После **полного** удаления `002` со всех столов следующий экземпляр получает `002`, если все более ранние ID этого типа заняты. Если экземпляр остаётся на другом рабочем столе, его ID занят. Существующие ID автоматически не переименовываются, чтобы не потерять настройки.

Клики на вкладки рабочих столов, создание и удаление столов, добавление, копирование и удаление виджетов теперь обновляют интерфейс без `location.reload()`; те же функции используются сочетанием `D + Alt + Tab`. Полный сброс локального хранилища, напротив, перезапускает страницу для очистки памяти приложения.

## Фон HQ и активный виджет

Стандартный фон заменён на `client/src/dashboardx-urban-background-hq.webp` (1672 × 941 пиксель, оптимизированный WebP высокого качества) из нового сгенерированного изображения. Старый фон 1672 × 941 больше не используется. Пользовательские обои по URL остаются приоритетными и не затрагиваются.

В пределах текущего рабочего стола **активным бывает только одно окно**. Клик по виджету, его кнопке, полю или выделение внутреннего поля клавишей Tab отмечает соответствующее окно `is-focus`, снимает активность с других и поднимает его над соседними. При смене стола запоминается активный ID каждого стола только в оперативной памяти текущей страницы (не в `localStorage`); если экземпляра больше нет, выбирается системный виджет добавления.

Для будущих виджетов предусмотрено событие `dashboardx:widget-keydown` на **активном элементе** `widget-element`. В `event.detail` содержатся `key`, `code` и `originalEvent`. Пока событие не назначает никакого действия стрелкам; набор текста в `input`/`textarea`/`select`, редактируемые поля и комбинации с Alt/Ctrl/Meta не перехватываются. Существующая команда `D + Alt + Tab` продолжает переключать рабочие столы.

Важно: macOS может самостоятельно округлять края значков в Dock и кэшировать старую иконку уже установленного Safari-приложения. Сама картинка в репозитории квадратная, и CSS-скругление к ней не применяется. При необходимости обнови иконку вручную в настройках веб-приложения или переустанови ссылку после обновления GitHub Pages.

## PRO-OPTIMA: интеграция с DashboardX

Новая категория **OPTIMA** и виджет `optimaSuppliers` («Поставщики») показывают актуальные данные Railway через `GET https://pro-optima-production.up.railway.app/api/admin/db` с Admin Token, заданным в системном виджете **«Настройки DashboardX»** (`dashboardSettings`). Возможности: поиск по названию/контакту/телефону, фильтр филиалов, просмотр графиков заявок и поставок, ручное обновление и обновление раз в 90 секунд во время активности страницы. Пока это **режим просмотра**, существующие формы PRO-OPTIMA продолжат редактировать базу как прежде.

В `localStorage["dashboardx.local.v1"].instances[instanceId].widgetState` сохраняются только строка поиска и филиал. Данные поставщиков не копируются в `localStorage`; они всегда читаются с Railway. При смене токена список обновляется.

Вместо `telegramSettings` используется `dashboardSettings`; прежние размещённые экземпляры автоматически открываются как общие настройки с сохранением старого ID/позиции. Новые экземпляры получают `dashboardSettings-000`, `-001` и т. д. Старый Telegram-токен, хранившийся только в оперативной памяти вкладки, после обновления нужно ввести вручную заново. В «Настройках DashboardX» кнопка «Удалить» удаляет только соответствующий токен, а общая «Очистить данные» удаляет и `dashboardx.credentials.v1`.

**Ограничение безопасности:** в GitHub Pages невозможно безопасно скрыть Admin Token от исполняемого JavaScript. Локальное хранение выполняется только по явному запросу пользователя. Для более безопасного использования и управления доступом нужно будет внедрить серверную авторизацию без передачи административного токена в браузер.

## OPTIMA — полный набор первоначальных виджетов (25 октября 2026)

Категория **OPTIMA** теперь содержит семь виджетов: `optimaSuppliers` (Поставщики), `optimaProducts` (Наименования), `optimaProposals` (Каталог прайс-листов), `optimaOffers` (Заказник), `optimaCompare` (Сравнение цен), `optimaStocks` (Остатки) и `optimaOrders` (Заявки). Все используют существующую Railway-базу PRO-OPTIMA через Admin Token из виджета «Настройки DashboardX». Все виджеты имеют отдельный ID и собственные фильтры в `widgetState`; база поставщиков, товаров, цен, остатков и заказов не дублируется в `localStorage`.

**Поставщики:** кнопка «Изменить» меняет название, контакт и телефон; кнопка «Заменить» открывает полный редактор карточки и списка графиков заявок/поставок с подтверждением. Сохраняется исходный ID поставщика и неизвестные поля записи; при переименовании обновляются связанные наименования поставщиков у товаров. Сохранение идёт PATCH `/api/admin/db` с `baseRevision`. Конфликт HTTP 409 блокирует запись, пока пользователь не обновит данные. Никаких автоматических разрушительных изменений не выполняется.

**Остатки:** адаптивная таблица по товарам (строки) и филиалам (столбцы). Источник значений — последняя запись `stocks` на выбранную дату включительно. Отдельно отображаются «?» (данных нет), «0» (нулевой остаток), «—» (не используется), обычные значения и единицы. Фильтры: поиск товара/поставщика, филиал, поставщик, дата и состояние остатка. Таблица прокручивается горизонтально **внутри** виджета, не расширяя шапку и рабочий стол.

**Заявки:** история из `history` и запросы дат из `dateRequests`, с фильтрами филиала, статуса, даты и текста; состав заявки раскрывается в таблице. На этом этапе редактирование заявок, самих остатков, цен и наименований не включено — это безопасные режимы просмотра. Все разделы поддерживают ручное обновление и периодическое чтение Railway во время активности вкладки.

**Примечание:** фронтенд GitHub Pages не может гарантировать сохранность административного токена, хранящегося без шифрования в `localStorage`. Используйте личное устройство. Возможность редактирования поставщиков требует токена с действительными административными правами.

## OPTIMA — заявки по графику и отправка из виджета (25 октября 2026)

Виджет `optimaOrders` теперь по умолчанию показывает **по графику** список ожидаемых заявок на выбранную дату, с фильтром по производству, дню недели, статусу и тексту. Варианты «История» и «Запросы дат» сохранены. День недели изменяет дату на ближайший соответствующий день, а изменение даты обновляет выбранный день. Расчёт графика учитывает филиал, поставщика, назначенные товары/цены и одобренные переносы дат по текущей схеме PRO-OPTIMA; сервер отдельно проверяет допустимость перед записью.

Для каждой позиции показаны поставщик, производство, даты заявки и поставки, количество товаров и состояние «Не заполнена», «Получена от производства», «Подана в обработку», «Подтверждена оператором» или «Принята». Если заявки нет, явно выводится «Заявки от производства ещё не было». При отсутствии записи кнопка «Заполнить заявку» открывает внутри виджета редактор количества заказа и остатков; для отправленной заявки доступно исправление, для уже подтверждённой/принятой — только просмотр. Архивные заявки на выбранную дату не исчезают, даже если график изменился.

**Отправка только официальным путём:** временный PIN выбранного производства нужен для `POST /api/operator/login`, после чего заявка подаётся через `POST /api/operator/orders` с выданным операторским токеном. PIN не сохраняется в браузере и очищается после отправки/закрытия формы. Сервер проверяет график, доступность и статусы; сообщения о недопустимой дате или конфликте показываются пользователю. Административный токен DashboardX используется только для загрузки общего списка. Отправка происходит исключительно после подтверждения пользователя; никаких тестовых запросов к действующей базе нет.

Остальные виджеты OPTIMA не переписывались. Настройки каждого экземпляра (дата, день через дату, производство, режим, поиск, статус) хранятся в его `widgetState`, но заявки/производственный PIN не сохраняются в `localStorage`.

**Важный эффект отметки остатка «-»:** операторский сервер считает её пометкой «товар не используется» и исключает товар из дальнейших заявок выбранного производства. В форме добавлено отдельное предупреждение; не используйте «-» вместо нулевого остатка.

## Единая высота и прокрутка виджетов (25 октября 2026)

**Все** виджеты (включая OPTIMA, «Наименования», «Остатки», «Заявки», настройки, калькулятор, курсы валют и системный «Добавить виджет») ограничены высотой доступного экрана: `max-height = max(180px, 100dvh − --dashboard-head-height − 72px)`. В старых браузерах используется `100vh`. Высота шапки измеряется во время работы, поэтому многострочные кнопки/панели не перекрывают окна. Контент, превышающий ограничение, прокручивается **внутри тела виджета** (колесо мыши, трекпад, сенсорный экран), шапка и кнопки управления остаются сверху. Небольшие виджеты сохраняют естественную высоту.

Перетаскивание и изменение размера через нижний угол сохраняются; ручное увеличение высоты теперь упирается в рассчитанный верхний предел. Если в `localStorage` ранее была записана слишком большая высота окна, CSS ограничит видимый размер без удаления пользовательских настроек; при последующем ручном изменении сохраняется фактическая высота. Фильтры, состояние виджетов, токены и API не менялись.

## Виджеты DashboardX — интерактивная доработка (26 октября 2026)

Не изменяя OPTIMA, завершены следующие автономные сценарии:

- **NES Emulator:** локальный ROM `.nes` размером до 5 МБ через jsnes, частота примерно 60 FPS, авто-пауза при скрытии вкладки, отключение обработчиков при удалении окна, мультитач-кнопки, геймпад Gamepad API, независимый звук, пауза, Reset, полноэкранный режим. **Клавиши:** стрелки/WASD = D-pad; Z или J = A; X или K = B; Enter = Start; любой Shift = Select; P = Pause; R = Reset; M = Mute; F5 = локальное сохранение; F9 = загрузка. Сочетания клавиш действуют только в активном окне эмулятора (не в текстовых полях). Файлы ROM не сохраняются и не загружаются на сервер. Сохранения из jsnes `toJSON/fromJSON` хранятся в браузере по ID экземпляра и контрольной сумме ROM с возможностью экспорта/импорта JSON; большой save может не поместиться в `localStorage`. Для запуска требуется доступ к скрипту jsnes CDN при первой загрузке страницы. DashboardX не предоставляет коммерческие ROM-игры.
- **Аудио:** локальные файлы и список прямых HTTP(S)-ссылок, плейлист, перемотка, громкость, переключение, повтор, авто-переход. Локальные медиафайлы доступны только до закрытия окна/страницы; ссылки сохраняются по ID виджета.
- **Видео:** локальные файлы и прямые ссылки на медиа, пауза, ±10 секунд, скорость, Picture-in-Picture и полный экран. Видео и аудио отправляют общее событие воспроизведения и останавливают другие медиаплееры, чтобы не играли одновременно.
- **Калькулятор:** выполняет арифметику кнопками или клавишами, не использует небезопасный `eval`.
- **Покупки, игры, magnet-ссылки:** рабочие локальные списки с поиском, статусами, ссылками, удалением, импортом/экспортом JSON. У покупок есть цель, накопления и прогресс. Magnet-ссылки **лишь открываются во внешнем клиенте**; браузер не скачивает торрент и не получает реальный прогресс.
- **Binance:** выбор торговой пары и интервала графика, ручное обновление, сохранение предпочтений, явное состояние ошибки, общий UI-сигнал `dashboardx:crypto-price`. Данные публичные, при недоступности API нужно повторить позже.
- **Мировые часы:** системный часовой пояс, Алматы, Москва, Лондон, Нью-Йорк, Токио, UTC; формат 12/24 часа и копирование текущего времени.
- **Финансы:** фильтрация финансовой таблицы по периоду, экспорт CSV. Таблица и итог обновляются при добавлении дохода/расхода в другие виджеты.
- **Диагностика:** локальный журнал событий без значений токенов, очистка и экспорт текстового файла.
- **GitHub Control / Server Monitor:** запоминание выбранного репозитория/адреса по ID виджета. **Контакты:** локальный импорт VCF, поиск и экспорт VCF; контакты намеренно остаются лишь в памяти вкладки.

**Telegram без сервера:** Telegram Bot API — обычный HTTPS API, поэтому отдельные запросы теоретически можно выполнять браузером, если разрешён CORS. Но токен в клиентской программе открыт JavaScript и может утечь; приложение GitHub Pages не запускает код после закрытия вкладки и не может быть защищённым webhook-приёмником. Поэтому виджет сейчас безопасно формирует черновик, копирует текст и открывает официальное окно «Поделиться в Telegram» (дальше отправку подтверждает человек). Сохранённый в DashboardX токен Telegram этим виджетом не считывается и не передаётся на сторонние адреса. Для автоматических исходящих сообщений и надёжного получения обновлений нужна защищённая собственная служба/прокси, а не прямой вызов Bot API из браузера.

**Структура:** единые стили `client/css/widget-experiences.css` основаны на токенах действующей HORIZON AR темы; переиспользуются во всех перечисленных типах. Запуск локального медиа и NES не требует сервера DashboardX, но зависимости с CDN могут потребовать сеть при первом открытии. Фильтры, поля и настройки экземпляров хранятся в `widgetState` без дублирования базы PRO-OPTIMA. Никакие токены в новые поля сохранения не добавлены. В `main` OPTIMA не менялась.


## NES и взаимодействия пользовательских виджетов (26 октября 2026)

В NES доступны клавиатура (стрелки/WASD, Z/X, Enter/Shift), геймпад, сохранение F5, загрузка F9, пауза P, сброс R, звук M. Добавлены переназначение клавиш A/B/Start/Select (сохранение в состоянии **только NES-виджета**), скорость 0,5×–2×, CRT-линии и перетаскивание ROM прямо на экран. При запуске NES медиаплееры делают паузу; когда играет другое медиа, NES приостанавливается. Другие экземпляры NES тоже ставятся на паузу.

В списках игр, покупок и ссылок появилась кнопка «В Telegram». Она передаёт название/ссылку в открытый виджет Telegram как черновик через событие `dashboardx:share-text`. Существующий несохранённый текст не перезаписывается без подтверждения. Telegram Share работает из браузера **без собственного сервера**: пользователь выбирает получателя и подтверждает отправку. Прямые запросы к Bot API с сохранённым в браузере секретным токеном не реализованы, так как это раскроет секрет любому скрипту на сайте и не обеспечивает защищённого получения обновлений.

Стили `dx-experience` унифицированы для игровых, медийных и локальных списковых окон. OPTIMA-код и данные не затронуты. Используйте собственные законно полученные ROM-файлы; игры в проект не включаются.

**Детали клавиатуры/геймпада:** нажатия геймпада учитываются отдельно от переназначенной клавиатуры. При потере фокуса NES все игровые кнопки отпускаются, чтобы не «залипали» направления. Версии JS-реестра и оболочки обновляются вместе со страницей.
